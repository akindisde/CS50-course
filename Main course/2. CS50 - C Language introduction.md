Imagine you wanted to print out a 3 by 3 grid using "#" symbols, like building a wall : 

```c
#include <stdio.h>

int main() {
	int i, j;
	for (i = 0; i < 3; ++i) { 
		for (j = 0; j < 3; ++j)
			printf("#");
		printf("\n"); // the end of each row, starts another one	 
	}
	printf("\n"); 
}
```

It's really simple, you just need to think of it like this : 
I have 3 lines, and **each** line has 3 brick. 

--> When you say *"for each, we loop"*, you'll ***generally*** **nest** loops.

A better design will be :

```c
#include <stdio.h>

int main() {
	int i, j;
	const int size = 3; // if we wanna change, we do it once.

	for (i = 0; i < size; ++i) { 
		for (j = 0; j < size; ++j)
			printf("#");
		printf("\n"); // the end of each row, starts another one	 
	}
	printf("\n"); 
}
```

The `const` keyword indicates that this variable declared with it will **not be able to change** during the execution after it's assignment. 

--> If you change the `const` variable during coding (giving it another value), the compiler will pop an error for it.

--> Remember to keep your code styled well, for better understanding, reviewing, and debugging.

Introducing the **do_while loop,** Even a better solution would be : 

```c
#include <stdio.h>

int main() {

	int i, j;
	int size;
	
	do {
		printf("enter a positive size for the square : ");
		scanf("%d", &size);
	} while (size < 0); 
	
	for (i = 0; i < 3; ++i) { 
		for (j = 0; j < 3; ++j)
			printf("#");
		printf("\n"); // the end of each row, starts another one	 
	}
	printf("\n"); 
}
```

The do_while loop executes its blocks at least once, because it checks the condition **after** that.

Now we talk about implementing **functions** in our code.

Functions are one of the best parts in coding. Why ? Simply because you can create a function that does something and return values to you *invoking* it (*using/calling* it) *whenever and wherever you want*, especially if you have some parts of your code that are **duplicated**. 

when you **define** (you specify how they function in code) functions, you do that generally **below main**, it's a style convention. 

let's type the program above but this time with functions implemented : 

```c
#include <stdio.h>

int get_size(void);
void print_grid(int size);

int main() {
	
	// get size of grid
	int size = get_size();
	
	// print grid
	print_grid(size);
}

int get_size(void) {
	int size; 
	
	do {
		printf("enter a positive size for the square : \n");
		scanf("%d", &size);
	} while (size < 1); 
	return size;
}

void print_grid(int size) {

	for (int i = 0; i < size; ++i) { 
		for (int j = 0; j < size; ++j){
			printf("#");
		}
		printf("\n"); // the end of each row, starts another one	 
	}
}
```

A lot going on here, but again, simple it is. 

We specify the type of value the function returns, that's why we have the `int` before the `get_size` function.

The `void` keyword before the function name means it *returns nothing*, when it's inside the parentheses after the functions names, it means that functions take no *arguments*.

Since we are <u>defining</u> the functions, we are also declaring their *parameters* (the place where the arguments gets passed in to the function), so you see `int size` which is something you're familiar with, but this time it's telling the compiler that the argument passed in should be an *integer and nothing else.* (it sets the rules for what's passed in)  

One very important thing to note here, Since the code is compiled *from top to bottom*, once the compiler reaches the line you invoked a declared function in, it will ask you (through an error) to **declare** (to tell the compiler it exists before you invoke it) it.

You do that by *declaring it before the main function*, but don't get it mixed up, you're defining under the `main` but declaring above it.

--> You can define functions above main directly, but it'll get annoying to scroll down to find main.

Introducing the **operators** by building a calculator in C : 

```c
#include <stdio.h> 
#include <cs50.h> 

int main(void) {
	
	int x = get_int("x: ");
	int y = get_int("y: ");

	int z = x / y;
 
	printf("%d\n", x + y); // %d or %i for integer 4
	printf("%d\n", x - y); // -2
	printf("%d\n", x * y); // 3
	printf("%d\n", x / y);
	
}
```

It's a good time to mention that each type you declare has a size limit to it. For example, the `int` type is given 32 bits generally (it depends on the machine) and every number is represented in binary in the **RAM** (random access memory) and in the **CPU** registers, if you exceed that size limit, you'll get problems.

32 bits, **singed**, will be half positive and half negative. meaning that the smallest number to represent in 32 bits is 
`-2147483648` and the highest number you get is `2147483647`.

So, when you try to give x and y *2 billion each* and add them, you'll get a random result, because the **result is the same type as the operands, therefore has the same size limitation.** and this situation is called **integer overflow** (losing bits)

--> You can try and add the `unsigned int` or `long int` type to x and y to see how the result now is not affected because the space for negative numbers is added for the positive numbers and now the highest number to store is `4294967295`.

These here are the format specifiers for different types :

![[Pasted image 20240709105648.png]]

`%li` and `%ld` are for the long integers (64 bits)

Another possible problem with operators is **truncation** (losing the decimal part in a floating point number) for example when divide 1 by 3, you should get 0.33333...3 but if you're operands are `int` typed, C deals with them as integers, so the result of the division will not have a decimal part.

--> ***Remember, the result type is ALWAYS dependent on the manipulation of variable types.***

C provides a solution of such problem, which is **type casting**, it basically means; telling the program in what type should it manipulate the variables as. For example 

```c
float z = x / y; // int x = 1 and int y = 3 --> z = 0.000 
```

But like this : 

```c
float z = (float)x / (float)y; /* int x = 1 and int y = 3 --> 
z = 0.333 */  
```

Because you're telling the program to do the operation with **temporary** change of types. 

--> Type casting changes the types just for that specific operation not for the whole program.

The same way with the `float` type, we have the **floating-point imprecision** (simple precision 32 bits -default- / double precision 64 bits)

if you ask for 20 digits after the decimal point for example:

```c
printf("%.20f", z); 0.33333333333333333333333....
```

you'll get random ones after a certain level.

You can use the `double` type to solve the problem (long float / double precision)
