Now here is the program that will compare strings for us : 

```c
#include <stdio.h>

// Function to compare two strings
// Returns 0 if strings are equal, negative value if str1 < str2, positive value if str1 > str2
int compareStrings(const char *str1, const char *str2) {
    for (int i = 0; str1[i] != '\0' || str2[i] != '\0'; i++) {
        if (str1[i] != str2[i]) {
            return str1[i] - str2[i];
        }
    }
    return 0; // Both strings are equal
}

int main() {
    char str1[100], str2[100];

    printf("Enter the first string: ");
    fgets(str1, sizeof(str1), stdin);

    printf("Enter the second string: ");
    fgets(str2, sizeof(str2), stdin);

    // Remove newline characters from fgets input
    str1[strcspn(str1, "\n")] = '\0';
    str2[strcspn(str2, "\n")] = '\0';

    // Compare the two strings using the custom function
    int result = compareStrings(str1, str2);

    if (result == 0) {
        printf("Strings are equal.\n");
    } else if (result < 0) {
        printf("String 1 is less than string 2.\n");
    } else {
        printf("String 1 is greater than string 2.\n");
    }

    return 0;
}
```


35. **Custom Function `compareStrings`**:
   - This function takes two pointers to constant character arrays (`const char *str1` and `const char *str2`) as parameters.
   - It uses a `for` loop with an index `i` to iterate through the characters of `str1` and `str2`.
   - Inside the loop, it checks if the characters at index `i` in `str1` and `str2` are equal (`str1[i] == str2[i]`).
   - If they are not equal, it returns the difference of their ASCII values (`str1[i] - str2[i]`), indicating which string is lexicographically smaller or larger.
   - If one string is shorter than the other but all characters compared so far are equal, it considers the shorter string as smaller.
   - If both strings are equal up to the length of the shorter string, it returns `0`.

36. **Main Function**:
   - Declare two character arrays `str1` and `str2` to hold the input strings.

37. **Input**:
   - Prompt the user to enter the first string using `printf` and read it using `fgets()`.
   - Repeat the process for the second string.

38. **Remove Newline Characters**:
   - Remove newline characters from `str1` and `str2` after reading input using `strcspn()`.

39. **String Comparison**:
   - Call the `compareStrings()` function to compare the two strings.

40. **Output**:
   - Print the result of the comparison based on the return value of `compareStrings()`.

41. **Return Statement**:
   - Return `0` to indicate successful execution of the program.

This approach uses a simple `for` loop to compare strings character by character without relying on the standard library function `strcmp()`. It provides a basic framework for string comparison in C.

Introducing `malloc` and `free`.

These are functions commonly used in programming languages like C and C++ to **manage memory dynamically.** They are included in `<stdlib.h>` :

42. **malloc:**

   - **Purpose:** The `malloc` function is used to allocate a block of memory of a specified size during the execution of a program. This memory is allocated from the heap, which is a region of memory used for dynamic memory allocation.
   
   - **Usage:** When you call `malloc`, you specify the size of the memory block you need in bytes. For example, `malloc(10)` allocates a block of 10 bytes. The function returns a pointer to the beginning of this allocated memory block.
   
   - **Return Value:** If `malloc` successfully allocates the requested memory, it returns a pointer to the allocated memory block. If it fails (due to insufficient memory, for example), it returns `NULL`.
   
   - **Example:** In C, you might use `malloc` like this:

     ```c
     int *ptr = (int *)malloc(5 * sizeof(int));
     ```

This allocates an array of 5 integers (`5 * sizeof(int)` bytes) and assigns the pointer to `ptr`.

43. **free:**

   - **Purpose:** The `free` function is used to deallocate (release) memory that was previously allocated using `malloc` or a related function like `calloc` or `realloc`.
   
   - **Usage:** When you no longer need a dynamically allocated memory block, you call `free` and pass it the pointer that points to the beginning of the allocated block.
   
   - **Effect:** `free` returns the memory back to the heap, making it available for future `malloc` calls or other dynamic memory allocations.
   
   - **Example:** Continuing from the `malloc` example above, you would use `free` like this:

     ```c
     free(ptr);
     ```

This deallocates the memory block pointed to by `ptr`. After `free(ptr)` is called, `ptr` should not be accessed anymore unless it is reassigned by another memory allocation function.

In summary, `malloc` is used to allocate memory dynamically at runtime, and `free` is used to release that memory once it is no longer needed. Proper use of these functions helps manage memory efficiently and prevent memory leaks in programs.

Let's now talk about swapping value to two variables. For example : 

```c
int a = 10;
int b = 12;
```

At the end of our swapping function we should have : 

```c
// a = 12 and b = 10
```

You can never do that we just the actual two variables to be swapped, you'll need another **temporary variable.**

If you attempt to do this : 

```c
a = b;
```

You'll have :

```c
// a = b = 12
```

And you've overwritten the content of `a`.

The right way to do it is this : 

```c
void swap(int a, int b) {
	int tmp = a;
	a = b;
	b = tmp;
}
```

Even if the idea is correct here, the implementation is poor and even incorrect, can you tell why ?

--> Remember that the values passed to the array are not the actual variables, but **copies of those variables.**

![[Pasted image 20240717231758.png]]

When we say "not the actual variables" or "copies" we're talking about other addresses in the memory.

`swap` function will never swap the actual values that way, so we need to ***pass the actual variables by giving the function their addresses in the memory*** to change them directly.

You should now make the difference between **passing arguments by value (copies of those arguments)** and **passing the arguments by reference (the function accessing them through their addresses).**

To correct our code, we should include pointers : 

```c
void swap(int *a, int *b) {
	int tmp = *a;
	*a = *b;
	*b = tmp;
}
```

![[Pasted image 20240717231659.png]]

Another thing you should know about when function get *called*; a segment of memory is given to that function for it to use it in its execution.

Before we talk about that more, let's see how the memory is actually segmented in general.

All programs are stored in the **hard drive**, once you click them or run `./program` its machine code gets **loaded** from the hard drive to the RAM (random access memory), the segment for machine code is on top of all segments in the RAM by convention.

--> This way the CPU has *fast and ordered access to the data* in the memory following a specific architecture.

After it we have the segment for the **globals**; they are the variables that *all functions in your program have access to*.

Under it we have the **heap**, it's where memory gets allocated **dynamically** using `malloc` and other memory allocation functions.

--> When the heap is saturated due to not freeing the allocated memory, the programs crashes. You can imagine the heap **growing down** in size as more memory is allocated in it.


Finally, we have the **stack** all the way down in the RAM, it stacks up (grows up in size), it is the space where functions get executed including, as always, `main`.

In the stack, you have all the ***arguments and variables*** that the called functions use to work.

Now you should've guessed it, that when you **call too many functions** (***especially recursively***) or **allocate too much
memory**, the stack and heap will -sort of- **bump** into each other (no more space) and you'll get a segmentation fault.

49. **Stack Overflow :**

- **Definition:** Stack overflow occurs when a program exhausts its available stack memory space.

- **Stack Memory:** The stack is a region of memory where local variables and function call information (such as return addresses and parameters) are stored during program execution.

- **Cause:** Stack overflow typically happens due to recursive functions or excessive allocation of local variables in functions, where the cumulative space used by these variables exceeds the available stack space.

- **Consequences:** When a stack overflow occurs, it can cause the program to crash. This crash is often due to overwriting the stack's boundary, leading to corruption of critical data like return addresses.

- **Prevention:** To prevent stack overflow, developers should:

    - Limit recursion depth or refactor recursive functions into iterative ones where possible.
    - Be mindful of function call depth and the size of local variables.
    - Increase the stack size if the programming environment allows.

 2. **Heap Overflow :**

- **Definition:** Heap overflow occurs when a program writes to a memory location outside of the allocated heap memory block.

- **Heap Memory:** The heap is a region of memory where dynamically allocated memory resides. Unlike the stack, which has size limits and is managed automatically, heap memory is managed manually by the programmer (through `malloc`, `calloc`, `realloc`, `free`, etc.).

- **Cause:** Heap overflow typically results from improper use of dynamic memory allocation functions (`malloc`, `calloc`, etc.). For example, writing more data into a dynamically allocated buffer than it was originally allocated to hold.
 
- **Consequences:** Heap overflow can lead to program instability, crashes, and security vulnerabilities. It can overwrite critical data structures, manipulate program execution flow, or even facilitate remote code execution attacks in certain cases.
 
- **Prevention:** Developers can prevent heap overflow by:

    - Properly checking bounds when copying data into dynamically allocated memory.
    - Using safe string and memory manipulation functions that ensure bounds checking (`memcpy_s`, `strncpy`, etc.).
    - Implementing memory allocation and deallocation practices that avoid dangling pointers and double freeing.

 3. Buffer Overflow

- **Definition:** Buffer overflow occurs when a program writes data beyond the boundary of a fixed-size buffer, either on the stack or the heap.
   
- **Cause:** Buffer overflow is often due to programming errors, such as using unsafe functions that do not perform bounds checking (e.g., `strcpy`, `gets`) or failing to validate input sizes.
  
- **Consequences:** Buffer overflow is a serious security vulnerability. It can lead to corruption of adjacent memory, execution of arbitrary code, privilege escalation, denial of service, or unauthorized access to sensitive information.
  
- **Prevention:** To prevent buffer overflow, developers should:

    - Use safe string and memory manipulation functions that perform bounds checking (`strncpy`, `snprintf`, etc.).
    - Validate input sizes and ensure that data copied into buffers does not exceed their allocated size.
    - Implement stack canaries or compiler features (like `-fstack-protector`) that detect buffer overflows at runtime.

When the program starts, `main` gets some space in the stack, when `main` calls `swap`, this last function will have a space for it too.

When `swap` is done executing, the memory given to it will be garbage memory, not used, but probably has the leftovers of the `swap`.

Here's the catch, the two segments for `main` and `swap` are not necessarily accessing the same variables. 

And now we should start calling that space each function has as the **scope of the function.** 

Simply and generally, if you pass arguments by value to a function, they'll be changed ***inside its scope as copies of the original variables they represent***. Every change that happens then, stays inside the function's scope and not shared with the other functions **unless this function changes a global variable.**

**File Operations in C :**

50. **File Pointers:**

   - In C, file operations are managed using a `FILE` pointer from the `<stdio.h>` header file. This pointer is used to interact with files and represents the connection between your program and the file.

51. **Opening a File:**

   - Before you can read from or write to a file, you must open it using `fopen()` function.
   - Syntax: `FILE *fopen(const char *filename, const char *mode);`
     - `filename`: Name of the file to open.
     - `mode`: Specifies the purpose and permissions of the file operation (`"r"`, `"w"`, `"a"`, `"r+"`, `"w+"`, `"a+"`, etc.).

52. **Reading from a File:**

   - Use functions like `fscanf()`, `fgets()`, or `fread()` to read data from a file.
   - Example:
   
     ```c
     FILE *fp;
     char buffer[100];

     fp = fopen("example.txt", "r");
     if (fp == NULL) {
         perror("Error opening file");
         return -1;
     }

     fscanf(fp, "%s", buffer); // Example of reading using fscanf

     fclose(fp);
     ```

53. **Writing to a File:**

   - Use functions like `fprintf()`, `fputs()`, or `fwrite()` to write data to a file.
   - Example:
```c
     FILE *fp;

     fp = fopen("example.txt", "w");
     if (fp == NULL) {
         perror("Error opening file");
         return -1;
     }

     fprintf(fp, "Hello, File!"); // Example of writing using fprintf

     fclose(fp);
```

54. **Closing a File:**

   - Always close a file using `fclose()` when you are done with reading or writing operations.
   - Example:
     ```c
     FILE *fp;

     fp = fopen("example.txt", "r");
     if (fp == NULL) {
         perror("Error opening file");
         return -1;
     }

     // File operations...

     fclose(fp); // Close the file when done
     ```

55. **Error Handling:**

   - Check for errors after every file operation (`fopen`, `fclose`, `fread`, `fwrite`, etc.). Use functions like `feof()` and `ferror()` to detect end-of-file and error conditions, respectively.

**File Modes :**

- **"r"**: Open file for reading. The file must exist.
- **"w"**: Open file for writing. If the file exists, it is truncated to zero length. If the file does not exist, it is created.
- **"a"**: Append; open or create file for writing at the end of the file.
- **"r+"**: Open file for both reading and writing. The file must exist.
- **"w+"**: Open file for reading and writing. If the file exists, it is truncated to zero length. If the file does not exist, it is created.
- **"a+"**: Open or create file for reading and writing at the end of the file.
